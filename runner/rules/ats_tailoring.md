## ATS TAILORING (one application = one tailored resume)

Most applicant tracking systems (ATS) rank or filter on the posting's own words and on location. A generic resume
is often dropped before a human reads it. For EVERY posting:

1. Read the posting and copy 8-15 keywords exactly as written (tools, skills, responsibilities, seniority, language).
2. Build or pick a resume for THIS posting:
   - the posting's exact job title appears in the summary line and in the first sentence of every free-text box;
   - a "Matching this role" skills line reuses the posting's vocabulary, but ONLY for skills the candidate really has
     (check against `profile.json`). Keywords that are not true are dropped, never added. Truth beats score.
   - use the posting's wording instead of synonyms (e.g. "lead generation" if the candidate did outbound prospecting).
3. LOCATION MATCH: put the posting's city in mind. If the posting is in the candidate's home city, show it. If it is in
   another city where the candidate is allowed to work, keep the real home city and add "open to relocation to <City>"
   (never claim to already live somewhere else, never use a fake address). For remote postings write "open to remote work".
   Postings in countries where the candidate has no work authorization follow the authorization rules, truthfully.
4. Resume language = posting language. One-page PDF, plain text layout (no tables, columns or images) so the ATS parser
   reads it. After uploading, read every pre-filled field and fix parsing errors before submitting.
5. Fill form "skills"/"tags" fields with the same truthful keywords. Never keyword-stuff, never repeat a term to game ranking.
6. Log which resume file and which keywords were used for each application, so response rates can be compared per variant.
